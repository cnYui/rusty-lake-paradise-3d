# 进度与存档：成就历史、本机存档、第一灾通关自动进入第二灾、菜单门禁

时间：2026-10-19 21:22

## 需求（用户）

1. 成就要有历史记录并保存；
2. 看一下小红书那边能不能给每个账号加存档，直接保存在浏览器本地；
3. 第一灾通关后现在直接回主页面、进不了第二灾：做成联动——第一灾完成后自动进入第二灾，不用退回主页面；主页面也能选第二灾，但没通关第一灾时不能选。

## 复盘：改之前是什么样（证据在源码里）

- `src/main.js` 每次启动都 `state.wipeAll()`（原因是开放世界改版时要清掉旧版固定镜头流程的存档）：存档、全局成就 `rlp3d.achievements`、`rlp3d.last` 都在启动时被删，**成就根本没有跨启动保留**；只有 `rlp3d.settings`（音量）能留下。菜单里的“继续游戏”只在“菜单选了另一章 → 重载”这一次重载里有用。
- 存档只在过场结束 / 开章 / 返回菜单时写，没有自动存档；存档版本是 `v: 1`。
- 通关结尾卡（`ui.ending`）只有“返回主菜单”一个按钮。没有任何“通关记录”，菜单里第二灾只看 `load` 有没有。
- 一个页面只能装载一章（`src/main.js` 的 `ensureChapter`）：换章要把选择记进 `sessionStorage` 再 `location.reload()`。
- 成就面板只列“当前页面已登记的成就定义”：装着第一灾时只有第一灾的 5 个，第二灾的 3 个要等装载第二灾后才会出现；也不显示解锁时间。

## 小红书那边能不能“每个账号存档、存在浏览器本地”（2026-10-19 查在线文档 `https://miniapp-sandbox.xiaohongshu.com/minitool/doc` 和本地 Skill 1.7.0 references）

- 文档原话要点：每个小工具有独立的存储，**按小工具隔离**；没说按账号还是按设备隔离。
- `getLaunchOptions` / `window.xhs.launchOptions` 文档只列了 `miniToolEnv.userDataPath` 和 `miniToolEnv.buildVersion`，**没有用户 / 账号标识**。所以“给每个账号单独分键”做不到：游戏拿不到账号。
- 文档明说容器“无法保证 `localStorage`、`sessionStorage`、`IndexedDB`、Cookie、Cache 始终可用，也无法保证其数据持续有效”；Storage API（客户端 9.46+）、文件系统（9.49+）的清理时机文档没写，只说卸载、清数据后可能丢失。
- **结论**：能做，但实际语义是“这台设备上小红书里这个小工具的本地存储”，同一部手机换小红书账号会不会共用、换设备会不会带过去，文档没说，我没法验证（只能真机）。我按用户要求用 localStorage，不接 Storage API；存不进去时游戏照常玩，只是不保留，菜单会明说。

## 设计决策

- 档案（`rlp3d.profile`）和章节存档分开：`{ ach: { id: { t 首次解锁时间, zh, en, ch 章节 } }, cleared: { 章节id: { t } } }`。“重新开始 / 新游戏”只清那一章的存档，成就历史和通关记录保留；只有设置里的“重置进度”全清。成就记下当时的名字，没装载那一章时菜单里也能显示。
- 存档版本升到 `v: 2`，旧版 v1 不再读（那是“启动即清档”时代写的，和现在的流程是否兼容没验证过）。但旧数据里有价值的两样并进档案一次：`rlp3d.achievements`（成就 id 数组，时间记 0）、带 `plagueN_complete` 旗标的旧存档（算通关）。
- 启动不再清档；`?autotest=1`、`?demo=1`、`?fresh=1` 仍每次空白（测试要确定性）。标题菜单期间 `state.saving = false`，免得章节 setup 触发的自动存档写出一份空存档让菜单误以为有进度。
- 自动存档：`flag / inventory / view / achievement` 变化后 500 ms 合并存一次；`ui.locked`（过场进行中）就等 800 ms 再试，避免存下半截状态；`pagehide` 立刻存。不依赖 `visibilitychange` / `document.hidden`（小工具那条教训）。
- 解锁规则放在章节注册表 `requires`（目前只有第二灾 `requires: 'plague1'`；第四灾不依赖第二、三灾，不写），逻辑在新文件 `src/core/progress.js`（`chapterStatus` = open / locked / soon，`nextChapter`、`resumeChapter`、`liveSave`）。`?chapter=N` 开发跳转不经过菜单，不受锁；新增 `?unlock=1`（`?wip=1` 也算）让菜单跳过这把锁。
- 通关记录：`main.js` 的 `watchClear` 监听章节的通关旗标（`completeFlag`，默认 `<id>_complete`），一立起来就记，不等结尾卡；`startChapter` 读档后旗标已立也补记一次。
- 结尾卡：有下一章（编号 +1，已开放且已解锁）就出现“进入第二灾 · 蛙灾”（主按钮）和“返回主菜单”，按钮出现后倒数 8 秒自动进入（用游戏时间，页面在后台时不走）；点“返回主菜单”或关掉结尾卡取消倒数。进入下一章 = `main.js` 的 `switchChapter`（沿用 sessionStorage + 重载，因为一个页面只能装一章）：第二灾有没打完的存档就继续，否则新开。第二灾结尾后第三灾还没开放，所以只有“返回主菜单”。`?autotest=1` / `?demo=1` 不自动倒数（`ui.autoAdvance = false`），免得 `RLP.autoplay()` 通关后页面自己跳走。
- 菜单：第二灾卡片没通关第一灾时显示“未解锁”（虚线边框，点了提示“通关第一灾后解锁”）；通关的章节卡片右上角打勾；▶ 指向“最近玩的没打完的章节 → 第一个没通关的已开放章节 → 从头重玩”，状态行写“继续：…”或“下一章：…”；存储不可写时状态行写“这里不能保存进度，关掉后会从头开始”。成就面板按章节分组（第一灾 / 第二灾，各自“已解锁 / 总数”，通关的标“已通关”），已解锁的写首次解锁时间，没有成就表的章节里解锁过的放进“其他章节”。设置里加了一行说明“进度、通关记录和成就保存在这台设备的浏览器里……”，“重置进度”之后菜单重画（锁和通关勾跟着变）。
- 启动时 `bootChapterNumber()`：没有 `?chapter` / 换章选择时，先装载玩家多半要点 ▶ 的那一章。目的：已经通关第一灾的玩家回来继续第二灾，不用先装载第一灾、点了再重载一次（手机上装载一章要好几秒）。
