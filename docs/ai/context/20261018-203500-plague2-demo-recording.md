# 第二灾通关演示视频录制与试玩发现的问题

时间：2026-10-18 20:35

## 目标

用户要求：自己把第二灾真实玩一遍，把整个游玩过程录成通关演示视频；玩的时候遇到 bug 自己修。

## 做了什么

### 1. 录制工具（新增，仅 dev 工具）

- `dev/demo_recorder.py`：录制器。
  - 画面：CDP `Page.startScreencast`（JPEG 质量 92，约 50 fps），按时间戳拼成 30 fps 的 H.264。没有用 Playwright 自带的 `record_video`，它固定约 1 Mbps、画面糊，也没有声音。
  - 声音：页面里给 `AudioNode.prototype.connect` 打补丁，把送往 `AudioContext.destination` 的声音再接一路到 `MediaRecorder`，分片经 `expose_function` 回传。游戏的声音全是 WebAudio 程序合成的，所以这样能录到环境音、音乐和音效。标题菜单选章会重载页面，每个文档单独成一段，按页面里 `Date.now()` 的开始时刻放回时间线（画面时间戳也是同一台机器的墙钟，所以不需要手工对口型）。
  - 假光标和点击涟漪：无头浏览器录不到系统光标，注入一个只用于录屏的叠层。
- `dev/record_plague2_demo.py`：演示脚本。只用玩家的输入（鼠标移动 / 点击、WASD、Shift、数字键），`RLP` 只用来读状态（位置、热点屏幕坐标、是否空闲），不直接触发热点、不传送。
  - 从标题菜单点“第二灾”开始，看片头标题，点岛进入海滩。
  - 走路：自己的 A* 找路（只看 `views.canStand`，和玩家能不能走完全一致），WASD 前进，用鼠标移到画面左右边缘转身、上下边缘抬头低头（按 `LOOK.deadX/deadY/roamYaw` 反推鼠标偏移）。
  - 每个阶段后有状态断言；失败时保存截图和 `RLP.info()`（`dev/shots/plague2/demo/fail-*`），并仍然合成一个 `plague2-demo-partial.mp4` 便于检查。
  - 用法：`python dev/record_plague2_demo.py [--size 1920x1080] [--fast]`；`--fast` 不录屏、停顿清零、过场加速，用来快速查 bug。
- 渲染用显卡：`--use-angle=d3d11 --enable-gpu`（Intel Arc 约 60 fps）；`shot.py` 里的 SwiftShader 只有约 2 fps，没法录。

### 2. 试玩中发现并修复的问题

- **神殿凳子上的腰带几乎点不到**（游戏 bug，已修）。腰带是中空的细环（约 31×14×18 cm），点在环中间会穿过去点到凳面，镜头因鼠标靠边微微偏转时也容易滑出去。`src/chapters/plague2/temple.js` 给腰带加了一个宽松的点击盒（`makeProxy(.44,.17,.36,[0,.48,0],stool)`，挂在凳子上），热点对象换成它，可见的腰带模型不变。
- 以下是演示脚本自己的问题，不是游戏 bug，记下来避免重复踩坑：
  - 重载后画布还在做 CSS 入场动画，不能马上取画布矩形；标题菜单里有无限循环动画，`animation.finished` 永远不会完成，只能等有限时长的动画并加上限。
  - 同类物品（三只青蛙）用掉一个后仍保持选中，再按一次数字键会取消选中。
  - 镜头有转动惯性（鼠标回中后还会转一阵），点击前要等目标在屏幕上的位置停稳，并确认指针下确实是它再按下。

### 3. 事故记录（我自己的操作失误）

调试中我用 `taskkill /IM python.exe` 结束卡住的脚本，这会杀掉本机所有 Python 进程。被杀的 3 个里，一个是我卡住的脚本，一个是 `127.0.0.1:8080` 的本地游戏服务（已用同样的方式 `python -m http.server 8080 --bind 127.0.0.1` 重启，PID 18312，返回 200），第三个无法确认是什么。其余并行任务（日报渲染、章节预览的 playtest）没受影响。之后结束进程一律按 PID，且只结束自己启动的。

## 验证

- 快速模式（不录屏）：两次完整通关，约 160 秒，三个成就（第一只青蛙 / 水中倒影 / 一把生锈的钥匙），页面无报错。
- 真实速度 1080p 录制：见下面的结果段落。

## 结果

- 成片：`dev/shots/plague2/demo/plague2-demo.mp4`，1920×1080、30 fps、H.264 + AAC，9 分 57 秒，143 MB（`dev/shots/` 被 `.gitignore` 忽略，不进仓库）。另有 960×540 压缩预览 `plague2-demo-preview.mp4`（14.5 MB，供手机预览）。
- 内容：标题菜单点“第二灾” → 片头标题 → 点岛进海滩 → 睡莲五关 → 蛙卵盆六对 + 水中倒影 → 厨房拿碗 / 蜡烛 → 神殿拿木头 / 腰带 / 转盘锁 / 蛙笛 → Ida 吹笛 → David 系腰带拿青蛙 → 煮青蛙汤 → Gerard 喝汤吐钥匙 → 开木箱看回忆拿黑方块 → 神殿吊架 → 结尾卡“第二灾 · 完”。三个成就都拿到，页面零报错。
- 声音：游戏的 WebAudio 合成声音全程都在（开头 20 秒标题菜单没有声音，和真实游戏一致：第一次点击后才创建 AudioContext）。
- 逐段抽帧检查（联系表、David、Gerard 两段放大）没发现新的画面问题：人物比例、动作、物品栏第二列展开、成就粉笔图标、回忆里半透明的 Caroline 都正常。
- 回归：
  - `node --test dev/test_plague2.mjs`：5 项全过。
  - `python dev/test_plague2_browser.py`：160 步自动通关、真实鼠标 + 数字键完整通关（含腰带一步）、触屏完整通关、中途读档与重复同步、室内家具碰撞与进出原位、正常首页进入和键盘 / 触屏走动，全部通过，页面零报错、零失败请求。
- 复现 / 再录：`python dev/record_plague2_demo.py --size 1920x1080`（约 10 分钟实时 + 数分钟编码）；只想快速查 bug 用 `--fast`；想从中间阶段接着试用 `--resume-from phase_cube --state <失败现场 json>`。

## 遗留 / 观察

- 固定镜头里鼠标靠近画面边缘时镜头会小幅偏转，物体会跟着微微滑动；对很小或很薄的热点（比如修复前的腰带）会显得“点不中”。本次只加宽了腰带的点击区域；如果以后还有类似反馈，可以统一考虑“指针停在热点上时暂停边缘偏转”，这属于交互手感的取舍，没有擅自改。
