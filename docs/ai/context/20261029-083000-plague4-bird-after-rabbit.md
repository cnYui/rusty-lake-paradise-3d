# 第四灾：吃完兔子后点鸟仍提示“先让它吃掉兔子”（2026-10-29 08:30）

## 起因
用户在手机上（小红书 V1.0.17 / 网页同代码）反馈：兔子已经被苍蝇人吃掉，陷阱特写里点鸟还是弹“苍蝇人还在别处进食。先让它吃掉兔子。”，鸟吃不了。

## 原因
10-28 的修复（`20261028-190500-plague4-trap-bird-feedback.md`）让 `bird_trap` 在“石板支好 + 虫子放好”时说 `T.preyWait('bird', 苍蝇人已孵化)`，这句话只看苍蝇人孵没孵化，没看兔子吃没吃，所以吃完兔子后还是“先吃兔子”。

真正能吃鸟的是挂在 `W.bird` 上的 `bird_meal`，但陷阱的点击盒（`world.js` 里 `fatten(ctx, W.trap, { min: [1.2, 0.7, 1.0] })`）比鸟的点击盒大、在很多角度挡在鸟前面，射线先打到陷阱，`bird_trap` 赢。桌面 960×540 测试里鸟中心正好落在陷阱盒外，所以 10-28 的浏览器测试没测出来；手机横屏视角下点鸟多半先命中陷阱。10-28 之前同样的位置点了只会重复“盘沿可以支起来”，也是评论里“点小鸟没反应”的一部分原因。

## 改法（`src/chapters/plague4/story.js`）
- 进食动画抽成 `eat()`，循环里记进 `meals[id] = { ready, eat }`，`${id}_meal` 的 `onClick` 直接用它（行为不变）。
- `bird_trap` 在支好 + 放好虫子时：`meals.bird.ready()` 为真就直接 `meals.bird.eat()`，否则才说等待提示。这样点到陷阱或点到鸟都能吃。

## 验收
- `dev/plague4/test_plague4_browser.py` 捕鸟陷阱一段：兔子没吃时点鸟提示“先让它吃掉兔子”；吃完兔子后真实鼠标点 `bird_trap` 的点击盒，断言 `p4_bird_eaten` 变真、没有再弹“先吃兔子”；再把鸟复原后点 `bird_meal` 也能吃。修复前这条新断言会失败。
- 本机：`node --test dev/plague4/test_plague4.mjs` 19/19；`python dev/plague4/test_plague4_browser.py` 全部通过（自动通关 133/133、真实鼠标 / 数字键 91 次交互、新加的“点陷阱也能吃鸟”）。第一次跑时新断言读到了上一句残留的说话条（先清空说话条再点），不是代码问题。
