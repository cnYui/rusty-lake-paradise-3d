# 第一章完整可玩化计划

## 当前事实

- 核心引擎、视图、热点、状态、物品栏和 Three.js 世界已存在。
- `src/chapters/plague1/beach.js`、`forest.js`、`lake.js` 当前均为空占位模块。
- 开场会把相机放到总览位置，但没有 `overview` 视图或热点定义，因此画面无法继续推进。

## 实现目标

补齐第一灾“血灾”的三段固定镜头点击解谜流程：海滩、森林、湖区。所有交互使用现有 `views`、`hotspots`、`items`、`state` 和 `ctx` 合约，支持存档同步和 walkthrough 自动验证。

## 方案

1. 在章节 setup 中创建视图、场景道具、导航热点和物品配方。
2. 使用 `world.anchor()` 作为镜头和道具定位的唯一位置来源，使用 `makeProp()` 复用已有模型。
3. 通过 flags 表示机关阶段，通过 inventory 表示可消耗道具；`sync()` 只负责从状态恢复显示状态。
4. 先保证端到端可玩和自动流程，再补充局部表现，不改变核心引擎契约。

## 验证

- 浏览器启动后可从总览进入海滩。
- `RLP.autoplay()` 完成第一章 walkthrough。
- 关键视图和热点在 `?debug=1` 下可见，错误数组为空。
