# 键盘物品栏、边缘转向视角与室外全程漫游

## 需求

1. 物品栏改用键盘数字键切换；合成时依次按两个数字键（例如先按 1 再按 2）。
2. 鼠标视角以左侧游戏画布（不是整个窗口）的中心为中立点，可以连续转 360°；原来只能转一百多度就停住。
3. 开局进入海滩后不再出现固定机位、左右 / 后退箭头，改成完全自由、可以走来走去的 3D 探索；不要 Pointer Lock，只保留最简单的鼠标点击和鼠标视角。

## 修改前的实际情况（浏览器复现）

- 漫游时只有 Pointer Lock 状态下鼠标才改变视角；不锁定时移动鼠标视角完全不动。
- 漫游中按 Esc 会退出漫游，回到 `beach_mid` 固定机位并显示左右 / 后退箭头，鼠标只能带动 ±35° 的视差；从船特写返回 `beach_right` 后也是固定机位。
- 早期的“按鼠标位移累计角度”方案在指针碰到屏幕边缘后就无法继续转，这就是“只能转 180° 左右”的来源。
- 总览用的 `overview_gate` 隐形代理（12×8×3 m）在漫游时也生效，从海滩点天堂门会先命中它，`gate_hand` 实际点不到；autoplay 直接调用热点 API，没有暴露这个问题。
- 漫游门禁只挡了栅栏 x∈(-24, 24) 的范围，可以从栅栏两端绕进森林；小屋门没开也能走到灵魂小径和湖区。

## 设计决策

- **视角模型**：指针相对画布中心的偏移决定转向角速度而不是角度。中心死区（水平 38%、垂直 50% 半宽）内不转，死区外按平方曲线加速，贴边约 2.4 rad/s；水平无上限，俯仰限制在 [-0.9, 0.45]。指针在画布外（物品栏）、离开窗口、过场锁定、弹窗、切换镜头时都不转。镜头切换后指针要先移动 18 px 才重新生效，避免停在 ▼ 箭头上的指针一回到漫游就带着视角往下转。漫游中指针处于转向区时光标显示左 / 右（上 / 下）箭头。
- **固定镜头**（总览、室内布景、谜题特写）：同样以画布中心为中立点，但只做小幅偏转（特写 0.12 rad、其它 0.14 rad，可用 `spec.look` 覆盖）并在指针回到中间后自动回正，保证点钉子、插销时画面稳定。室内布景只有后墙和两侧短墙，四周是黑色虚空，所以不开放 360° 环视。
- **室外全程漫游**：室外、非 `closeup`、非 `fixed` 的视图都是开放视图，进入即漫游，不显示方向箭头、去掉拖拽切视图和 Esc 退回固定镜头；Esc 统一打开暂停菜单。总览标成 `fixed: true`，保留“远景 → 点天堂门 → 进入海滩”的开场。
- **进出特写**：从漫游进入特写 / 室内时记住漫游位姿，▼、S 或 ↓ 返回时恢复原来的位置和朝向；触发返回的那次 S 在松开前不会让人继续后退。
- **脚本转场**：漫游中脚本切换室外地点（开天堂门 → 森林小径、开小屋门 → 灵魂小径）时，直线畅通就滑行过去，隔着墙或树就黑场切换，避免穿模。
- **碰撞与门禁**：`world.colliders` 汇总树干（森林与阔叶树根部圆）、房屋、神殿、塔、栅栏（只在门洞断开）、小屋木墙（只在门洞断开）、小船和几个大件道具；视线高度跟随 `groundHeight` 地形。章节门禁改由章节用 `views.addRoamGate()` 注册：天堂门未开时只能停在栅栏和门板前（z ≥ 40.6），小屋门未开时不能越过木墙一线（z ≥ -13.2）。碰到障碍时沿墙滑动。
- **热点**：漫游时只开放挂在开放视图上的热点（总览、特写专用的热点不再生效），最远拾取 24 m；删除了只为固定机位服务的 `boat_entry` 代理；点击始终取鼠标所在位置。
- **物品栏**：只用键盘，槽位不接收鼠标、右下角标出键位。1–6 选中；再按同一个键取消；已选中时按另一个数字键合成，配方不对时两个槽位一起抖动；快速连按两次查看物品。带 Ctrl / Alt / Meta 的组合键不拦截，避免抢走浏览器的 Ctrl+1 等快捷键。

## 顺带修复

- `soul_path` 机位与灵魂角色站在同一点，相机会落进灵魂身体里；机位移到两棵帘幕树干南侧（21, -16.8），透过缝隙看灵魂和后面的湖。
- `beach_right` 机位原来背对小船，改为看向小船（只作为测试跳转目标，autoplay 不再报“船不在画面内”）。
- 棺材升起前只有一条透明水线可点，漫游时斜看很窄；在血池中心加了 4.6×3.6 m 的隐形点击区，仍属于 `coffin` 热点。
- 棺材第二次点击原来要求逻辑视图是 `blood_pool`，漫游时逻辑视图不一定是它，改为“不在棺材近景里就进入近景”。
- 提示文字在顶部字幕条显示期间会排队，不再被物品名字幕吞掉；新增漫游、物品栏、返回三条一次性提示。

## 已知限制

- 无头 SwiftShader 开着渲染只有约 2.7 fps，引擎单帧最多推进 0.05 s，所以依赖时间的测试（转身角度、走动距离）要先关掉渲染（`RLP.ctx.engine.renderEnabled = false`）。
- 碰撞只覆盖树干、建筑和几个大件道具；岩石、竹丛、桶等小物件仍可穿过。热点拾取不考虑墙体遮挡（只限制 24 m 距离）。
- 浏览器调试面板被隐藏时 `requestAnimationFrame` 暂停，依赖帧的 `RLP.goto()` 等调用会一直等待。
