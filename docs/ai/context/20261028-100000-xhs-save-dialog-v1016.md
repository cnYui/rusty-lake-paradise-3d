# 2026-10-28 小红书 V1.0.16 候选包：“保存进度”改成弹提示框（已部署，未提交审核）

## 起因
- V1.0.15（存档改 Storage API + 启动卡顿修复）仍被驳回，原因和 V1.0.14 一字不差：“小工具功能缺陷，可能是页面按钮无法点击，重点排查页面功能完整性”。见 `20261027-103000-xhs-storage-and-boot-freeze.md`。
- 审核历史：V1.0.13（bulbfix）通过，V1.0.14 / V1.0.15 驳回。V1.0.14 新加的主要是暂停面板的“保存进度”按钮。它点了以后只改面板底部一行小字，容器里存不了档时还显示“这里不能保存进度”，看起来像“点了没反应 / 功能不完整”。用户选了方案 2：按钮保留，点了弹一个明显的提示框。

## 改动（提交 `8294722`，DeepSeek 工人改、我审过）
- `src/core/ui.js` 的 `openSettings()`：点“保存进度”先收起暂停面板，再用 `ui.dialog` 弹框，按钮“知道了”，点完重新打开暂停面板（dialog 意外返回 null 时也重开，不会卡在没有面板的状态）。三种结果：
  - 保存成功：标题“已保存”，正文“已保存：<时间>”；
  - 存不了档：标题“无法保存”，正文“当前环境无法保存进度，关掉后会从头开始。”；
  - 过场中：正文“正在播放过场，结束后会自动保存。”
  底部小字照旧写一份。这一处网页版也跟着改。不用 alert。
- `dev/minitool/test_storage_xhs.py`：setStorage 全失败的那一项改成检查弹框（标题“无法保存”、不含“已保存”），点“知道了”后暂停面板（“暂停”）重新出现。共 40 项。
- 存储层和启动卡顿的修复照旧保留。

## 其它“点了只改一行小字 / 没反应”的按钮（只列出，没改）
1. **菜单里锁着的章节卡**（“未解锁”的第二到第四灾；“敬请期待”的第五灾）：点了只有错误音效 + 卡片抖一下 + 菜单底部状态行换一句“通关第一灾后解锁 / 敬请期待”。审核员用的是新号，进来时第二到五灾全是锁着的，最容易点到这几张卡；静音时只剩抖一下和一行小字。**嫌疑最大**，建议改成弹框说明。
2. **提前菜单（V1.0.12 起）选了章节以后**：世界还没搭好时，菜单整体 `pointer-events: none`，只在状态行写“正在载入，马上开始……”。慢机上这段可能有十几秒，期间“成就”“设置”和所有卡片都点不动。建议加明显的载入遮罩和进度，或者在载入期间仍允许打开成就 / 设置。
3. **▶ 开始按钮**：`resumeChapter` 为空时 `if (!resume) return;`，点了什么都不发生（正常存档下很少出现，但要兜底）。
4. **“新游戏”**：`first` 为空时同样直接 return（理论上不会出现）。
5. 设置里“重置进度”之后只在状态行写“进度已重置”（菜单会重画，问题不大）。
