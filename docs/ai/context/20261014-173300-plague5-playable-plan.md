## 视频核对后的修正

- 0:05–1:20：天堂门、盆栽生菜、病牛彩色斑点。补成对斑点交互，消除后才能取肉和挤奶。
- 1:25–5:35：木桶、菜地和白底连点。菜地采用三轮可移动菜苗、行列占格数约束；连点采用五轮节点度数约束，接受所有满足数量且连通的解，避免隐藏硬编码答案。
- 5:45–7:25：祖母、刀、菜单、绞肉和煎锅。锅只烹调牛肉；番茄和黄瓜交给祖母切片，取消初版“蔬菜放锅但不消耗”的错误状态。
- 7:55、17:00：牛奶与奶酪。空桶装奶后倒入林间木桶，再取得奶酪。
- 15:45–19:15：Gerard 吃汉堡后进入厕所。补厕所、金色面具和回忆入口；黑方块从回忆取得，不能提前从连点图获得而绕过汉堡。
- 19:30–20:55：回忆、黑方块、神殿圣水盆和下一灾画框。复用吊架与圣水盆动画，增加第五灾专用画作，避免照搬第二灾红衣女人结尾。
- 汉堡配方、菜地布局与连点题面是根据上述机制重新设计的第一版，具体排列与食材层数仍需后续逐帧对照。

## 状态与模型

- 所有中途状态保存到 flags：斑点配对与选中、菜地轮次/位置/选中、连点轮次/边/当前点、汉堡层、加工/奶酪/回忆/神殿进度。
- `sync()` 根据 flags 完整恢复显示，支持重复调用和新游戏双向恢复。模型 `userData` 只是显示缓存，不作为玩法真值。
- 所有新增工厂使用 `p5_` 前缀；复用公共角色、岛屿、房屋和神殿，临时谜题区域自带灯光。
- 普通室外持续自由漫游；房屋使用 `roam: true` 及室内家具碰撞；出入特写恢复漫游原位。天堂门与小屋开局开放，神殿在回忆完成后开放。

## 验收

1. Node 规则测试：菜苗越界/重叠、行列约束、连线撤销/度数/连通、合法答案。
2. `dev/shot.py` 调用 `RLP.autoplay()`，检查完成旗标、`bootError` 与运行错误。
3. 实际鼠标、数字键及触屏命中主要谜题与物品栏；检查半途存档、新游戏复位和反复 `sync()`。
4. 顺序抓取病牛、菜地、连点、厨房、饭桌、厕所、回忆、神殿与画作；避免同时开启多个 SwiftShader 进程挤占渲染资源。

## 已发现的初版问题

- 95 步旧流程在加速时通过；默认 15 秒步骤上限会把软件渲染下耗时约 26 秒的画作动画误判为卡死，采用既有 `RLP.timeScale` 加速验证。
- 初版截图没有显式跳转时，`autotest=1` 只启动引擎，URL 的 `view` 不会自动开始章节；正式截图必须调用 `RLP.start()` 或 `RLP.goto()`。
- 临时布景缺灯、星图接近水平侧视、牛被过近相机裁切、厨房相机在前墙外、拾取只有不可见代理、饭桌大代理遮住交互均需修正。
