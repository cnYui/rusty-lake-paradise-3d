## 3. 返工和走弯路的地方

1. **鼠标视角（10-08，约 6 份记录）**：累计位移 → Pointer Lock → 简单鼠标视角（用户说不要 Pointer Lock）→ 全局鼠标视角 → 又加回 Pointer Lock 和准星 → 最终靠边转向。
   错在假设：“只能转 180°”的真因是累计像素位移到屏幕边缘就停，Pointer Lock 只是绕开问题。中间几份记录只做了 `node --check`，当时 `shot.py` 还不可用。
2. **`autoplay` 通过，真人点不动**：入口只有 60×40 像素可点；棺材钉子 5、6 被隐形点击区盖住（`proxy()` 漏设 `userData.proxy`）；10-18 神殿腰带点不到。10-14 的“真实鼠标”测试仍点腰带正中心，所以照样通过。
3. **第一灾首版与原作不符**：盘子角度不对、缺木桶、小屋侧面能看到灵魂（剧透）；记忆场景人物最初是占位建模；10-14 人物又整体重做，因为旧人物在各章靠缩放凑镜头，同一人物身高从 1.18 到 2.39 m。
4. **小工具颜色实验**：假设“红色惹的”，红 → 橘黄 → 紫各提审一轮；当时已把“文字里的血、图标上的血灾”列为风险，却没和颜色一起改，V1.0.2 白提交了一轮。V1.0.3 改文字加紫色通过，V1.0.4 单独换回红色也通过，所以更可能是“血”字——**这只是单次对照，证据有限**。做得对的一点：事先写下了“结果怎么解读”（`red-x-experiment`）。
5. **启动卡顿**：V1.0.0 因启动是一条不让出主线程的长任务被判“按钮点不了”，改成分段，但分得不够细；10-19 评论反馈闪屏，才再拆到约 90 次让出主线程并加轻量模式。Chrome 61 兼容问题（`catch {}`、`roundRect`、CSS `inset`）也是 10-12 才发现。
6. **V1.0.5 驳回，根因有两种说法**：记忆里是“隐藏时不启动渲染”，仓库记录里是 `build.py` 全屏补丁误删 `chapterOpen`。两边都没拿到平台侧证据，甚至不清楚实际上传的是哪个 ZIP。
7. **第二灾暂停与恢复**：两次因额度中断；8 个子代理刚读完简报就被停，没有写任何文件；一个联网调研代理 90 分钟无产出；10-14 核对时第二灾还是 `wip` 空壳。
8. **其他**：第四灾设计初稿把宝石石门放在小屋，会让寄居蟹与宝石互为前置，实现时改成神殿门；第五灾初版蔬菜放锅不消耗；参考视频 P06、P09、P10 下载后有一路流被截断，靠“视频流 + 音频流大小之和对比合并后体积”才发现。

## 4. 重复出现的错误类型和以后怎么避免

| 类型 | 具体实例 | 以后的检查项 |
| --- | --- | --- |
| A. 只测绕过真实输入的路径 | 点击区太小、钉子点不到、腰带点不到；`RLP.ready` 为真但 `bootError` 不为空，菜单没显示；森林数组坐标传给 `Vector3.copy()` 产生 NaN | 每个新热点做射线网格扫描；真实点击测试要偏离中心 8–10 像素点一次；从无参数首页验证菜单；判“启动成功”必须同时看 `bootError` 为空 |
| B. 隐形点击区与可见性处理不一致 | `visible=false` 的点击球被射线跳过；`proxy()` 没标 `userData.proxy`；隐形盒盖住真正目标 | 隐形代理一律走 `makeProxy`；新增后用射线逐个核对谁先命中 |
| C. 平台限制事后才发现 | Chrome 61 / ES2017、容器 CSP 禁用 `<audio>` 的 data 地址、iOS 静音拨片、封面必填、Skill 版本 | 接入新平台先读官方文档，当天把限制写进 AGENTS 再动手 |
| D. 启动路径依赖外部状态或长任务 | V1.0.0 长任务；V1.0.5 隐藏时不启动（记忆版）；10-19 闪屏 | 加启动逻辑后，在 CPU 降 4 倍的手机视口下多轮取最长任务中位数；不在启动路径上等任何外部东西 |
| E. 并行会话互相覆盖，早期还没有版本控制 | 10-12 整批还原备份覆盖了 `minitool.css`；同日出包失败清空了别人的 `dist-audio`；10-18 `taskkill /IM python.exe` 杀掉了 8080 本地服务 | 动手前先 `git status` 并比对 mtime；只在当前内容上改；结束进程只按 PID，且只结束自己启动的 |
| F. 对照原作太晚，或靠缩放凑 | 第一灾首版；人物缩放 0.65–1.5；参考帧事后才补对 | 新章节、新人物先抽参考帧再建模；`scale` 必须为 1，先用 `dev/cast.html` 对身高 |
| G. 批量动作和记录没有“全集合”核对 | 评论通知三次重复（本记录第 1 节）；10-19 的 commit `d65f089` 改写了已有记录 `20261019-094500-…`（62 行删除），违反“不覆盖历史记录”；一份记录写“验收通过前不开放菜单”，后来状态变了 | 批量动作前先导出“已处理名单”，对全集合（跨帖子、跨顶层/楼中楼）去重，并考虑对方改名；状态更新一律另起新记录 |
| H. 单次对照结论用得过满 | “血字是原因”；V1.0.5 的两种根因；闪屏“推测” | 记录里分开写“证据 / 推断 / 没验证”；记忆只写已证实的结论 |
| I. 先发后验 | 10-08 部署后没从公网跑 `autoplay`，第二天才补；宣传片片尾卡写着“小红书小工具”，而审核当天还没通过 | 部署后从公网跑完整流程；成品上写“已上架”之前先核对真实状态 |

## 5. 已沉淀的规矩 vs 还没沉淀的

**已经在 `AGENTS.md` 或记忆里**：室外自由漫游和室内 `roam` 规则；鼠标只管点击和视角、不用 Pointer Lock；触屏规则；公网部署路径不能出现 `/vendor/`、Mac 的 8080 是 Docker 容器；小红书打包补丁只替换命名函数并从无参数首页验证；启动不阻塞主线程与轻量模式；第一、二灾限开放；人物真实身高与 `scale = 1`；各章验收入口；记忆里有小工具上传流程与审核史、提交前需用户明确同意、并行会话先比 mtime。

**只存在于某份记录里、`AGENTS.md` 还没有**：
- 真实输入验证为什么必须做（`autoplay` 绕过了点击链路），以及隐形代理 / `visible=false` 的射线规则；
- Chrome 61 / ES2017 基线、容器 CSP、永远竖屏、文件白名单、ZIP 10 MB；
- 玩家可见文字用 x 代替“血”（已进入 `src/`，commit `f981e4d`）；
- 视频下载要逐流校验和解码；
- 无头浏览器约 2.7 fps：用 `renderEnabled=false` 与 `timeScale`，隐藏面板时 `requestAnimationFrame` 会暂停；
- 脚本改写文件要保留 CRLF；
- 批量评论通知先建“已通知名单”再去重（本记录新增）；
- 公开仓库先扫私有信息（只在记忆）。

**记忆本身的问题**：`MEMORY.md` 里写“V1.0.6 已修好待提交”，而 10-19 的记录已显示已提交审核，索引需要更新。
