# 小红书小工具审核未通过后的修复（分段启动 + 排查工具）

## 背景

- 用户自己在小红书后台点了“发布小工具”，V1.0.0 审核 **未通过**，原因：“小工具功能缺陷，可能是页面按钮无法点击，重点排查页面功能完整性”。
- 用户要求：修改后重新上传一版，**先不要提交**（不勾协议、不点“发布小工具”），把二维码留着给用户扫码试。
- 没有真机、拿不到审核端的画面，只能从“和银魂项目（同样的整体旋转 90° 通过了审核）相比，这个游戏多了什么”找最可疑的差异。

## 排查

- 点击链路：标题菜单的 ▶ / 新游戏 / 成就 / 设置都是 `click`；画布热点和触屏摇杆走 pointer 事件，只认 `pointerType` 为 touch / pen；
  存储访问（localStorage / sessionStorage）全有 try/catch；没有 `touchstart` 的 `preventDefault`。点击这条链路没有发现问题，旧测试 27/27 也说明模拟触摸能点中。
- **启动是一条不让出主线程的长任务**（最可疑）：`boot()` 里所有 `await` 等的都是已经完成的 Promise（esbuild 把动态 `import()` 打进了包里），
  于是“建世界 → 布置章节 → 第一次渲染（同步编译全部着色器）”连成一个宏任务。用 `dev/minitool/measure_boot.py`（手机竖屏 + 容器 CSP + CPU 降速）实测 **旧包**：
  - 不降速：页面 21.5 s 才触发 `load` 事件（软件渲染下第一次渲染占 17.8 s）；
  - CPU 降速 4×：30 s 内 `load` 事件都没触发（`page.goto` 超时）。
  慢手机上的表现就是：整段时间页面没响应、画面停在“载入中……”，容器 / 审核很可能当成“页面坏了、按钮点不了”。
  注意：这里是软件渲染（SwiftShader），着色器编译的绝对时间不等于真机；世界建造（纯 JS，1× 约 2.3 s，4× 约 11.6 s）是真实的计算量。

## 改动（游戏源码一行没动，全在 `dev/minitool/`）

1. `build.py` 补丁 3：对副本里的 `main.js` / `art/world.js` 做分段启动
   - `boot()` 每个阶段之间让出一帧（初始化画面 → 搭建天空和湖面 → 种树铺地 → 盖房子 → 布置场景 → 准备画面），`buildWorld` 改成 `async`；
   - 第一屏（室外）的着色器先用 `renderer.compileAsync`（带 20 s 超时兜底；支持 `KHR_parallel_shader_compile` 的 WebView 里不卡主线程，不支持就和原来一样同步编译），再 `render()`；
   - 启动改成页面 `load` 之后再开始，`load` 迟迟不来也会在 1.5 s 后自己开始。
2. `rotate.js`：
   - `window.__RLP_STAGE(文字)`：把阶段文字写到“载入中”页并让出一帧；
   - 没接住的报错（`error` / `unhandledrejection`）在画面顶上显示红色横幅（点一下关闭，15 s 后自动消失），真机上出事不再是“静悄悄点不动”；
   - **排查面板**：2 秒内连点画面左上角 5 下打开 / 关闭，显示窗口大小和像素比、是否转了 90°、触点数和粗指针、核数 / 内存、WebGL 版本和显卡、是否有并行编译、启动各阶段耗时、帧率、像素比、绘制次数 / 三角形数、最近一次按下的（类型、游戏坐标、点中的元素）、报错条数和最后一条；
   - 布局更稳：容器还没给 WebView 定大小（宽或高为 0）时保持上一次布局；`pageshow` / `load` / `visualViewport` 变化时重排，头 6 秒每 300 ms 对一次。
3. `minitool.css`：载入页上方加一个只用 `transform` 的转圈（由合成线程跑，主线程忙着建世界时也照转），报错横幅和排查面板的样式。
4. 新增 `measure_boot.py`（量启动耗时 / `load` 触发时间 / 阶段文字）；`test_minitool.py` 增加第 5 节（降速 3× 下 `load` 事件、阶段文字、排查面板的真实触摸连点、报错横幅）。
5. 旧包留作对比：`dev/minitool/_old/rusty-lake-minitool-v1.0.0-rejected.zip`。

## 验证（新包，同样的模拟条件）

- `measure_boot.py`：不降速 `load` 事件 0.1 s（旧 21.5 s）；降速 4× `load` 事件 0.2 s（旧 30 s 内不触发）；两档都依次显示 6 个阶段文字，`bootError` 为空、没有页面错误。
  总耗时基本不变（软件渲染下着色器编译才是大头），变的是页面在这段时间里**有响应、看得出在进展**。

## 没验证 / 风险

- **真机没测**，审核端的设备和环境不明。这次改的是“最可疑的原因”，不保证一定过审；用户扫码试用时，如果还有问题，连点左上角 5 下看排查面板，把截图发来。
- 世界建造和第一次渲染的计算量本身没有减少（慢手机上仍可能要等 10 秒以上），只是现在有进度提示、不再假死。如果真机上等得太久，下一步是做“按需建造室内布景”或降低首屏画质。
- 没有改旋转方向、安全区（容器返回钮会盖住游戏左下一小块，银魂项目当时多留了 24 px）。
