# 2026-11-09 小红书小工具加云存储（天堂岛）

## 起因
用户 11-09 看了创作者中心的小工具新能力（云存储 / 排行榜 / AI 文本 / 分享 …），要求给当前发布的两个锈湖游戏加上存储。天堂岛从 V1.0.15 起已经有本地 Storage API 存档层（`dev/minitool/storage_xhs.js`），这次在它上面加云存储：换设备 / 清缓存后能找回进度。

## 平台条件（来自 https://miniapp-sandbox.xiaohongshu.com/minitool/doc §3.16）
- 云存储是**内测**能力，客户端 ≥ 9.51.0；未授权返回 errCode 1006（排行榜 1005），要降级。
- 上传页「所需权限」里要勾「用户头像和昵称」（页面写着“若使用云存储、排行榜，则需申请用户头像和昵称的权限”）。
- collection 里每条 content 必须是对象、≤ 64 KB；批量 ≤ 100 条；逐项判 status（SUCCESS / FAILED / UNKNOWN）；接口限频 150 QPS。

## 设计（只改 `dev/minitool/storage_xhs.js`，游戏源码和 build.py 的补丁不动）
- 只同步 `rlp3d.save.<章节>` 和 `rlp3d.profile`；设置、最近章节是设备自己的，不上云。
- collection `rlp_saves`，一个键一条：`{ k, v, t }`，`v` 是游戏写的原始字符串；单条 UTF-8 > 60000 字节跳过。
- 启动：本地层就绪后再等云最多 1.2 秒（`ready` 因此最多多等 1.2 秒）；save 取 `savedAt` 较大的，profile 取并集，规则和本地迁移相同；云更新的写回本地（cache、Storage API、localStorage），本地更新 / 云没有的排队上传；云更慢也不拦启动，回来后在后台合并。
- 运行期：写入攒 30 秒上传；切后台 / pagehide 立即上传；`removeItem`（重置进度）同时删云上那条，并在云还没回来时记墓碑，不让云把旧存档“复活”。
- 降级：版本不够、缺接口、errCode 1005 / 1006 / 10003、云读失败、连续 6 次写失败：云层关闭，只用本地层；云读失败整次放弃，不当成“云上没有”去覆盖。add 结果 UNKNOWN 时下次先查一遍对账，不重复新增；两台设备同时第一次上传造成的重复记录合并后删多余的。
- 设置面板那句说明（只在小红书包里改写）改成“进度、通关记录和成就保存在小红书里；支持云存储的新版小红书还会同步到云端，换设备也能接着玩（不支持时只保存在这台设备上）。”

## 验收
- `python dev/minitool/test_cloud_xhs.py`（新）33/33：模拟 `window.xhs.miniTool` 的云接口，覆盖版本边界、云更新 / 本地更新 / 云没有 / profile 并集、30 秒窗口与 pagehide、重置进度不复活、云慢 / 挂起、未授权 1005 / 1006 / 10003、过大跳过、UNKNOWN 对账、FAILED 重试、重复记录合并。
- 现有 `test_storage_xhs.py`、`test_minitool.py`、`test_share_xhs.py` 对打好的包重跑，结果见 `upload/README.md` 的这一行。

## 没验证的
没有在真机（≥ 9.51）上试：云存储是内测能力，这个 appId 有没有授权、「用户头像和昵称」权限勾上后用户端会不会多一次授权弹窗，都要上线后看。未授权时游戏会自动退回本地存档。
