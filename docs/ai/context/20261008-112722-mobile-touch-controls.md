# 手机触屏版：电脑端与移动端双端适配

## 需求

把当前版本做成可以在手机上用触屏玩的版本，同时保持电脑端可用。

## 设计决策

- **按最近一次输入切换界面**：手指 / 触控笔按下 → `#stage.touch`（触屏界面）；鼠标真正移动 → 切回电脑界面。启动时 `pointer: coarse` 的设备直接进入触屏界面。触屏逻辑只处理 `pointerType` 为 touch / pen 的指针，电脑端的鼠标靠边转向、WASD、数字键物品栏完全不变。
- **走路**：漫游时在画面左侧 42% 内按住拖动 = 浮动虚拟摇杆（底座出现在按下处，平时在左下角淡淡提示）。推得越远越快，推到 90% 以上逐渐变成奔跑；中心 12% 为死区。
- **转视角**：在其它位置拖动按手指位移转（不是靠边转速），划过整个画面宽度约 195°，向右拖向右转、向上拖抬头，松手再拖可以一直转。固定镜头（总览、室内、特写）里拖动只在该镜头的环视范围内偏转，松手回正，保证谜题画面稳定。
- **轻点**：手指移动不超过 12 px 才算轻点，交给 hotspots 拾取；hotspots 改成按指针分别记录按下位置和最大移动距离，推摇杆的同时另一根手指照样可以点，拖动后回到原处也不会误判成点击。
- **物品栏**：触屏界面下槽位可以直接点，规则与数字键相同（点一下选中、再点取消、点另一件合成、快速点两下查看），键位数字隐藏；电脑上槽位仍不接收鼠标。
- **方向**：手机按横屏设计（与原作一样的宽画面 + 右侧物品栏）。手机竖着拿（竖屏、粗指针、宽度 < 700px）时全屏提示“请把手机横过来游玩”；平板竖屏仍可玩，16:9 舞台上下留黑边。没有做竖屏专用布局：第一人称双摇杆操作在竖屏上很别扭，固定特写的构图也是按宽画面设计的。
- **全屏**：浏览器支持全屏时（安卓 Chrome 等）右上角显示全屏按钮；触屏界面下点“开始”会顺便进入全屏并尝试锁定横屏。iPhone Safari 不支持网页全屏，按钮不显示。加了添加到主屏幕后全屏打开的 meta。
- **手机浏览器细节**：舞台尺寸改用 `dvh`（地址栏伸缩时不被裁掉）；`overscroll-behavior: none` 与 `touch-action: none` 防止下拉刷新、回弹、双击放大；阻止长按菜单和 iOS 双指缩放；音频在 `pointerup` / `touchend` 时解锁（手机浏览器只认这类激活事件）；检视器里点部件的移动阈值对手指放宽到 12 px。
- **界面尺寸**：触屏界面下 ▼ 等箭头的点击区域放大到约 47px（手机横屏），图标放大；齿轮、菜单链接、按钮文字放大；槽位约 45px。
- **性能**：像素比上限电脑 2、手机 1.75。新增动态分辨率：每满 90 帧或 2 秒统计一次，超过一半的帧慢于 26 ms 就把像素比降 0.25（手机最低 0.75、电脑最低 1，只降不升，避免来回跳）；启动前 4 秒和切到后台时不统计；自动化测试（`navigator.webdriver`）里关闭。

## 涉及文件

- `src/core/touch.js`（新增）：触屏模式切换、虚拟摇杆、拖动转视角。
- `src/core/views.js`：读取摇杆驱动走路、读取拖动位移转视角；只让鼠标参与靠边转向；`dropPointer()`。
- `src/core/hotspots.js`：按指针分别判断轻点，触屏阈值 12 px，触屏不做悬停拾取。
- `src/core/ui.js`：槽位响应手指、`ui.touchMode`、全屏按钮、竖屏旋转提示、检视器点击阈值。
- `src/core/engine.js`：像素比上限与动态分辨率。
- `src/main.js`：初始化触屏模块；手机音频解锁；阻止长按菜单与双指缩放。
- `src/core/debug.js`：`RLP.info()` 增加 `touchMode`、`pixelRatio`，`roam.touch` 显示摇杆状态。
- `src/chapters/plague1/text.js`、`beach.js`：触屏版操作提示。
- `styles.css`、`index.html`：触屏界面样式、摇杆、全屏按钮、旋转提示、dvh、移动端 meta。
- `README.md`、`ARCHITECTURE.md`、`AGENTS.md`：操作说明与约束同步。

## 验证

- `node --check`：所有修改过的模块通过。
- 手机模拟（Playwright：横屏 844×390、`isMobile`、`hasTouch`，用 CDP `Input.dispatchTouchEvent` 派发真实多指触摸），27 项全部通过：识别为触屏界面、横屏不提示旋转、16:9 舞台按屏幕高度铺满；轻点天堂门进入漫游并显示摇杆；左侧拖动推摇杆向前走、松手复位；右侧向右拖右转、松手再拖累计超过 360°、向上拖抬头；双指边走边转；槽位约 45px，点一下选中、再点取消、先后点两件合成、快速点两下查看、点 ▼ 关闭检视；选中物品后点空地取消选择；轻点小船进入特写、特写里不显示摇杆、拖动小幅环视且松手回正、返回箭头约 47px、点 ▼ 回到原位；无运行时错误；竖屏 390×844 显示旋转提示；电脑 1280×720 无触屏时界面保持原样（无摇杆、槽位不接收鼠标、显示键位、无全屏按钮）。
- 手机从标题菜单开局：开始按钮约 49px，点开始 → 片头 → 总览 → 点门进入海滩，顶部显示触屏版提示，音频上下文为 `running`，无错误。平板竖屏 810×1080：不提示旋转，舞台 810×456。
- 动态分辨率：在约 1 fps 的无头 SwiftShader 里手动打开，像素比按 1.75 → 1.5 → 1.25 → 1 → 0.75 逐级下降，绘制缓冲同步缩小，无错误。
- 电脑端回归：真实鼠标键盘测试 26/26、9/9 通过；`RLP.autoplay()` 77/77、`plague1_complete: true`、无错误（剩余 `fish`、`holder` 两条机位警告与之前相同）；演示章节 25/25。

## 已知限制

- 没有真机测试，触摸行为来自 Chromium 移动端模拟；iOS Safari 的全屏和锁定横屏不可用，只能靠旋转提示。
- 手机竖屏没有专用布局。
- 动态分辨率只降不升；如果开头一段场景特别重导致降档，后面即使轻松也不会升回去。
