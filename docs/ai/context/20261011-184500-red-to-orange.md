# 小红书审核未通过：把游戏里的红色全部改成橘黄色

## 背景

- 创作者中心 → Builder hub → 小工具（`https://creator.xiaohongshu.com/new/red-app`）里，“锈湖：天堂岛3D”V1.0.1 状态 **未通过**，
  原因栏只有一句“内容未通过平台综合审核”，没有具体条目；“历史版本”弹窗加载失败（获取历史版本失败，请重试），拿不到更细的说明。
- 上一版（V1.0.0）被驳回的原因是“功能缺陷”，已在 `20261009-171500-xiaohongshu-minitool-review-fix.md` 里处理；这次换成“内容”类，
  用户判断可能是画面里有血（本作第一灾就是血灾：湖水变血、水蛭、血壶……）。
- 用户的要求：把整个游戏里出现的红色部分全部改成橘黄色，先试一试。**没有重新上传、没有发布**——上传 / 发布要等用户确认。

## 做法

1. 备份：改之前把 `src/`、`styles.css`、`dev/minitool/minitool.css` 复制到会话草稿目录；旧 zip 另存为
   `dev/minitool/_old/rusty-lake-minitool-v1.0.1-uploaded-before-red2orange.zip`。
2. 扫描：对 `src/**/*.js`、`styles.css`、`dev/minitool/minitool.css` 里所有十六进制、`rgba()`、裸 `'r,g,b'` 字符串和 GLSL `vec3` 常量按色相 / 饱和度 / 亮度判定红色。
   判定原则：色相 ≥ 340° 或 ≤ 15°、饱和度和亮度都够的算红色（血、红屋顶、红斗篷、红花、水蛭、虾、红按钮……）；
   **棕色（头发、皮肤、木头、野猪毛、铜件、粉嫩的兔鼻子）不改**，不然整个游戏都变形。
3. 统一映射（脚本一次性生成，不是逐个手挑）：色相 → 约 34°（橘黄 30–38°），饱和度略提，亮度中调抬 0.12（否则深红映射后会变成棕色而不是橙色）；
   暗红 → 深琥珀。
4. 手工修正：
   - 湖面着色器（`src/art/lake.js`）的 `cRing1 / cRing2 / cShore / cDeep / cPool`：公式出来偏灰（被灰色湖面和雾稀释），手调成更饱和的橘黄
     （`#eba43a / #ddb27a / #e5982c / #e08a0f / #e9a63c`）；
   - 血触手着色器（`props_lake.js`，`vec3(0.62,0.22,0.22)`→`vec3(0.87,0.36,0.03)`，`vec3(0.50,0.06,0.07)`→`vec3(0.75,0.22,0.01)`，注意着色器里是线性空间）；
   - 溪流绘制里的 `RED` 数组（`props_lake.js`）；
   - 小船里的箱子 `#b28c81` 偏粉棕，改成 `#b79c7b`；
   - 文案里的颜色词：`plague1/text.js` 的“暗红色的血灌满了木桶。”→“橙黄色的液体灌满了木桶。”；演示章节 `_demo.js` 的红宝石 → 橙宝石。
5. `PALETTE.blood*` 键名保留（避免大面积重命名），数值已是橘黄，并在 `materials.js` 里加了注释说明。
