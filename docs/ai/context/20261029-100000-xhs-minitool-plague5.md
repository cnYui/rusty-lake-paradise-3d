# 2026-10-29 小红书小工具带上第五灾

## 起因
用户问小红书线上第五灾发布了没。创作者中心（Claude in Chrome）查到：天堂岛 V1.0.17（10-28 19:45 提交）已“生效中”，25.5 万人使用；V1.0.17 包（`rusty-lake-minitool-ch1234-clickfb-20261028-release.zip`）里第五灾 `load` 是 `null`、没有章节代码，菜单卡“敬请期待”，通关第四灾的结尾卡只有“返回主菜单”。原因是 `dev/minitool/build.py` 对第五灾做了置空。用户要求“在小红书带上第五灾”。

## 改动
- `dev/minitool/build.py`
  - 注册表里第五灾的 `load: null` 置空改成只在 `--ark`（口袋方舟 / 233 乐园）打包时执行；小红书包保留第五灾的 `load`，解锁条件沿用源码注册表的 `requires: ['plague1', 'plague2', 'plague3', 'plague4']`（两条断言都还在）。
  - 第五灾 `setup` 在 `world.setup` 与 `puzzles.setup` 之间加 `await window.__RLP_STAGE()` 让出一帧（和第四灾同样做法，启动 / 换章期间不出现不让出主线程的长任务）。
- `dev/minitool/test_minitool.py`
  - 空档菜单：第二到第五灾“未解锁”，第六灾起“敬请期待”。
  - 解锁顺序：新增“只通关第一、二、四灾（残档）”两章都锁着；通关第一到第四灾第五灾开放。
  - 新增 1f：第四灾通关结尾卡出现“进入第五灾 · 疫灾 / 返回主菜单”，真实触摸点它，页面重载进入第五灾且无启动错误；第五灾结尾卡后面没有可进入的章节。
  - 第五灾完整流程 autoplay + 成就 `p5_harvest / perfect_constellation / sickly_cow` 全部拿到。
  - game.js 里“死”“血”字：原来只按汉字查，而 esbuild 输出是 `\uXXXX` 转义，查不到；补一条按转义写法查（剔掉第三灾提示文案“拍死的蚊子”这一处，它在 233 提示按钮的 `hints.js` 里，小红书里不显示，早就在已通过审核的线上包里）。
- `AGENTS.md`：小红书小工具开放范围改成第一到第五灾，233 包仍是第一到第四灾。

- `text.js`、`hints.js`、`items.js`、画布文字（`props_p5.js` 的菜单牌 / 石板字）逐个查过：没有“血”“死”“杀”“尸”“毒”等字，没有需要改写的台词。
- 保留原文、但值得留意的词：章节名“疫灾”（菜单卡、章节标题卡、结尾卡）、成就“病牛”、台词“他的头缠着绷带”、“用刀取肉”“生肉”。一旦这一版被驳回、后台只给“内容未通过综合审核”，首选的改法是：章节名“疫灾”在小红书包里改成别的写法（和第一灾 `x灾` 一样处理），其次是“病牛”。
